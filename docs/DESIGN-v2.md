# deepseek-brain · v2 设计说明（仪器化改版）

> 这份文档解释 v2 为什么长这样，以及每一条视觉规则背后的功能理由。
> v1 的问题不是「不好看」，而是**装饰**：3D 大脑只是背景，粒子只是光点，界面只是卡片。
> v2 的唯一目标：让看到的东西**就是**插件正在做的记忆运算。

---

## 0. 一句话概念

**这不是一个仪表盘，是一台观测仪。**

把 DSH 里那个真实存在的记忆系统，当成一台需要被观测的生物仪器：中央是一颗悬浮的脑（唯一主角），
周围是仪器的边框——标本标注、刻度尺、目镜读数、时间转盘。界面本身越安静，脑就越像活物。

三条铁律：

1. **每个像素都在描述一次真实运算**：没有一条曲线、一个数字、一次闪光是客户端编造的。
   所有数值来自 `/api/state`、`/api/activity`、`/api/recall`；时间转盘真的让服务端重算强度。
2. **3D 结构承担功能**：区域不是贴图色块，而是记忆的容器与检索的路径；纤维束是检索真的会走的通路。
3. **反模板**：没有渐变、没有霓虹辉光卡片、没有圆角 16px 的 KPI 砖、没有紫蓝配色。
   视觉语言取自 19 世纪脑解剖图谱 + 射电望远镜控制台：墨底、骨白刻线、朱砂强调、宋体标题 + 等宽数据。

## 1. 两种观看模式

| 模式 | 观看者 | 看什么 |
|---|---|---|
| **观测**（默认） | 用户/评审 | 全脑：五区分布、纤维束、活跃程度、当前时间切片 |
| **目镜**（点击后） | 想追问的人 | 单个 engram：它为什么在这个位置、强度如何衰减、被谁检索过 |

观测模式用**电影感**（缓慢自转、呼吸式明暗、事件脉冲）；目镜模式用**显微感**（相机飞入、背景压暗、
其它 engram 退成轮廓、读数面板给出分解）。

## 2. Engram 形态学（彻底取代「光点」）

一条记忆在 3D 里是一个 **engram**，由三部分构成，每一部分都编码一个真实字段：

| 部件 | 几何 | 编码 |
|---|---|---|
| **核** nucleus | 低面数多面体（8–20 面） | 尺寸 ∝ `importance`，自发光 ∝ `salience`，形状按层区分 |
| **棘** spines | 3–6 条细丝，从核径向伸出 | 条数 = `importance`，长度 = `strength/5`，随 `salience` 收缩 |
| **纤维** fibers | 连向相关 engram / 区域束的曲线 | 语义三元组 `subject→object` = 一条真实纤维；情景与语义共享实体 = 一条「引用纤维」 |

层间差异不是换颜色，而是换**形态**：

- 感觉记忆：彗星状短痕（拖尾指向输入方向，`ttl` 内逐帧缩短）
- 工作记忆：环形（栈顶在环心，被搁置的话题压到环外半透明）
- 情景记忆：多棘星形（海马体内的索引节点）
- 语义记忆：多边形晶格（节点+边，`subject`/`object` 为端点）
- 程序记忆：双楔形（基底的「闸门」形态，`hits` 让楔口张开）

> 视觉密度靠聚合解决：同区 engram 超过阈值时按「同实体/同周」聚成 **conglomerate**（一团带棘的核簇），
> 点击后展开。这样 200 条记忆也不会变成一锅萤火虫。

## 3. 结构即运算（3D 建模的用处）

| 3D 结构 | 承载的真实过程 | 触发 |
|---|---|---|
| **白质纤维束**（海马↔颞叶皮层↔前额叶） | 检索时的激活路径 | `POST /api/recall` |
| **激活脉冲**沿纤维前进、按 `score` 概率在目标处分叉 | `hits[].score` 与 `parts` | 同上 |
| **脑室旁的海马索引环** | `topK` 的候选池 | 同上 |
| **时间切片平面**（沿前后轴缓慢推进的薄膜） | 当前 `at` 时间点 | 时间转盘 |
| **archive 外环** | 被遗忘/归档的记忆去向（永不物理删除） | `forget` / `decay` |
| **迁移路径**（海马 → 颞叶） | 睡眠巩固把高重要度记忆搬进长期区 | `POST /api/sleep` |
| **虚线幽灵 + `[已修正]` 标签** | 语义冲突的旧版本 | `correct` 事件 |
| **前额叶环内的环链** | 工作记忆话题栈（栈顶 = 环心） | `working.stack` |

## 4. 视觉语言（去模板化）

### 4.1 色彩

不使用紫蓝渐变。用**墨 + 骨 + 染料**：

| 角色 | 值 | 用途 |
|---|---|---|
| 墨底 | `#07080a` → `#0d0f12` | 背景（带极轻的纸张噪点，非纯黑） |
| 骨白 | `#e6e0d2` | 正文、刻度、细线（1px，`rgba(230,224,210,.13)`） |
| 朱砂 | `#c8482e` | 强调、警告、遗忘、当前时间指针 |
| 青瓷 | `#7b9f9a` | 次要数据、参考线 |
| 染料（五层） | 感觉 `#6fd3c4` · 工作 `#c9a63f` · 情景 `#d9617c` · 语义 `#87a44f` · 程序 `#c07a45` | **只给 engram 与纤维**上色；UI 外壳保持骨白 |

规则：界面外壳只允许骨白/朱砂/青瓷三色；五层染料只出现在 3D 与世界内的标记上。
这样色温统一，脑区颜色才显得「是标本的荧光标记」而不是「AI 生成的霓虹」。

### 4.2 排版

- 标题：宋体（`Songti SC`/`Source Han Serif`），字重 400，字号大而收敛，字距 +0.02em。
- 数据：等宽（`JetBrains Mono`/`ui-monospace`），`font-variant-numeric: tabular-nums`。
- 分区用**双细线**（上粗下细）而非卡片阴影；标签用**引线 + 端点小方块**（解剖图谱式）。
- 圆角 0–2px；无发光边框；hover 用「刻线下划线」与「方框 focus ring」，不用变色按钮。
- 所有数字右对齐到刻度列；单位后缀用小一号青瓷色。

### 4.3 控件

- **时间转盘**：环形刻度（-30d…+30d），指针朱砂，拖动时喉部显示 `at` 与半衰期读数。
- **拨档**（segmented）：三档「观测 / 目镜 / 剖面」，做成压印金属档位。
- **执行键**：压印按钮（内阴影 + 1px 双线），按下有 90ms 下沉动效；不用圆角渐变。
- 禁止：浏览器默认 slider、圆角胶囊 chip、阴影卡片、emoji 图标。

### 4.4 布局

```
┌──────────────────────────────────────────────────────────────┐
│ 观测条：ENCEPHALON · Fairy · 时间切片 -2.3d · λ0.050 · 事件#128 │  48px，等宽
├──────────┬────────────────────────────────────┬──────────────┤
│ 解剖板    │                                    │ 目镜读数      │
│ 五层标注  │           3D 脑（全出血）           │ engram 详情   │
│ 计数/刻度 │                                    │ 检索控制台    │
│ 260px    │                                    │ 340px        │
├──────────┴────────────────────────────────────┴──────────────┤
│ 观测台底栏：时间转盘 · 巩固 · 衰减 · 导出 · 手势提示            │  76px
└──────────────────────────────────────────────────────────────┘
```

窄屏（<820px）：3D 占满，解剖板折叠成顶部横向刻度条，目镜面板改为自下而上的抽屉（可拖拽高度）。

## 5. 事件编排（activity → 动画）

| 事件 | 动画（总时长 ≤ 1.2s，可叠加） |
|---|---|
| `observe` | 感觉带擦亮 → 一串短痕向 PFC 滑行 → 若 `kept` 则目标区出现新 engram 的核 |
| `recall` | 感觉带 → PFC → 海马索引环 → 命中区；索引环先被点亮一整圈（候选集在此成形），命中按 `score` 决定脉冲强度；主束沿途留下渐隐尾迹（单动态 `LineSegments`，`depthTest:false`），并按 `score` 从束上不同高度剥出 1–5 条侧支，越靠后越细越短 |
| `remember` | 目标区一次「凝聚」：核从 0 缩放，棘依次抽出 |
| `correct` | 旧 engram 变为虚线轮廓并外推 0.08 单位，新 engram 在旁诞生，两者之间一条细虚线 |
| `forget` | engram 沿外环滑出并熄成灰点，落入 archive 环 |
| `consolidate` | 情景 engram 沿迁移路径滑向颞叶，途中棘缩短（`detail` 被压缩），落点成为语义晶格 |
| `decay` | 按 `ids` 顺序逐个淡出（每个 60ms 间隔） |

所有动画都以 `prefers-reduced-motion` 与「低画质档」降级为静态高亮。

## 6. 性能预算

- 单 `<canvas>`；eneff 数量上限：核用 `InstancedMesh`（≤ 2000 实例），棘/纤维合并为**一个** `LineSegments`
  顶点缓冲（≤ 60k 顶点），脉冲用 `Points`（≤ 256）。
- 每帧只更新：相机、脉冲进度、`uTime` uniform；engram 缓冲区只在 state 版本号变化时重建。
- 目标：2019 年级核显 1440×900 下 ≥ 55fps；低画质档（无透射材质、无菲涅尔壳、棘线宽减半）≥ 45fps。
- 提供 `d` 键 HUD：`renderer.info` + 帧耗时 + engram/纤维计数，方便评审验证。

## 6.5 注意力聚焦

检索不是「点亮几个点」，而是一次注意力转移：命中簇在 2.6 s 内向质心收拢并被一圈细环圈住，非命中向外让开并压暗，钟形曲线进出。位移是显示层的偏移，不写入槽位坐标——所以「同一条记忆永远落在同一格」的确定性寻址不受影响。

## 6.6 话题热度

聚光是瞬态，热度是余温。每条活动事件按语义折算成五层的「被关注度」（写入 `+1.6`、检索命中 `+1.1`、修正 `+1.2`、睡眠 `×0.62`），统一按 **32 s 半衰期**衰减；热度既抬该层 engram 的亮度，也在该层解剖锚点处点亮一片加性光晕。于是「刚刚在聊什么」不需要读日志，看标本哪一块发亮就知道。

实测衰减：`episodic 3.87 → 1.81`（35 s，比值 0.468，与 32 s 半衰期的理论值 0.47 一致）。

热度分两级落地：**层热度**决定解剖锚点处那片加性光晕，**单条热度**（`APP.heatK[id]`）决定具体那一枚 engram 的亮度。写入、检索命中、修正都同时记到 id 上；`observe` 还会按话题文本在 engram 的标题/摘要里做一次子串匹配，把余温摊给相关的那几条（最多 6 条）。于是「亮的是那一簇」而不是整层——实测同一查询下 `支付流程` 那条 2.60、`夜跑` 那条 1.52。

**两条时间常数不同的通道**：热度（32 s）回答「刚刚被想起的是谁」，相关度（128 s）回答「上一次检索觉得哪条最像」。前者改亮度、后者改轮廓硬边，读数分两行写。实测：先 `recall 张伟 望京 开会`（命中 0.63 / 0.49），紧接着写一条新记忆，读数变成「关注：情景记忆 1.00 · 刚写下的新记忆」+「最相关：0.62 · 和张伟在望京开会」——两条线指向不同的记忆，这正是设计意图。


## 6.7 检索史

温度看得见还不够，还要能回看「刚才在找什么」。左栏底部是一条 12 条的时间轴：`时:分 · 查询 · 命中层刻度 + 命中数`，同一分钟内的多次查询补秒位区分。点一行就把 `{id, layer, score}` 原样喂回 `runRecallPulses`——聚光圈、命中收拢、纤维束全部按当时的载荷重跑，同一句话 4 s 内的重复回放不重复记账。
## 6.8 关联图

检索史回答「查过什么」，关联图回答「那次查到了什么、比上次多了什么」。中心是查询，四周是命中：半径与连线粗细按 `score`，颜色是层色，虚线外圈标记「上一次没有、这次新出现」的命中。下方一行做同话题对比——同话题的判定是**空格分词的共享实词比例 ≥ 0.25**（查询本身就是词串，比字级 bigram 稳），对比行会把共同词写出来（如「共同词：张伟」），再给 `+新增 / −落空 / =保留` 三个数。图挂在舞台左下角，窄屏（< 900 px）隐藏以避免和图注区打架。
## 6.9 图与脑的悬停联动

关联图上的节点带着 `data-id`，悬停时把 `APP.hoverId` 设成该条记忆的 id 并重排一次实例变换：命中的那枚 `hi = 1`、其余 `dim = 0.92`，浮卡底部给出「层 · 标题 · score」。这层悬停优先级高于选中与相关度，但低于检索聚光（聚光期间不打断）。浮卡自身 `pointer-events: none`，只有节点恢复 `auto`——所以鼠标可以从图上滑到标本上继续拖拽。
## 6.10 时间轴回放

检索史不只是一串行，它是一段可拖的时间。`range` 的值是「第几次检索」的小数坐标：整数处是真实记录，中间处按 `score × (1−f)` / `score × f` 把两次命中并成一个集合，喂给同一套 `setFocus`——于是拖动时命中簇在两个位置之间连续滑移，而不是跳帧。拖动期间 `APP.focus.hold` 把钟形曲线锁在峰值，松手才吸附到最近一格并重放纤维束。
## 6.11 检索节奏

把 12 次检索按真实时间排开会遇到一个问题：一次会话里既有 2 秒的连击，也有 5 分钟的走神，线性时间轴会把连击压成一根线。这里把相邻间隔先取 `log1p(Δt)` 再累加成横坐标——**横轴不是时间，是节奏**：爆发段挤成一簇，长停顿被拉成一段空白。每根刻度的高度随命中数增长（12 px 上限），颜色取首个命中的层色，当前那一次加粗。读数固定给出 `跨度 · 次数 · 最长停顿`，让「今天查得很碎」这件事第一次能被数出来。
## 6.12 检索史的来路

检索史不落盘，但也不随刷新消失：页面连上服务端时向 `/api/activity?since=0&limit=200` 要一次活动流，把 `kind === "recall"` 的事件按 `{at: ts, q: query, hits}` 重建成列表，与已收到的事件按「秒 + 查询串」去重合并，取最近 12 条。服务端的活动流本身是进程内环形日志（`ActivityLog`，默认 240 条），所以这条恢复能力**跨刷新、不跨重启**——这是刻意的：记忆本体落盘，认知活动不落盘。
## 6.13 进程世代

「历史是空的」有两种可能：这个进程还没查过，或者换了一个进程。这两件事对用户的心情完全不同，所以必须分开。`ActivityLog` 在构造时生成一个 6 位短 id（`this.boot`），`/api/activity` 把它一起返回；前端存进 `localStorage.brain3d.boot` 并在下次连上时比对，于是检索史标题会写 `进程 cgwcfu` 或 `新进程 garm36 · 历史已重置`，空态也会写「这个进程还没有检索记录」，而不是含糊的「还没有检索」。
## 6.14 世代指纹落盘

只把 `boot` 放在内存里，用户仍然不知道「这台机器被重启过几次」。所以 `MemorySystem.init()` 里加了一步 `stampBoot()`：把这次的 `{id, count, since, previous}` 写进 `stats.json`——同一份数据目录每打开一次，`count` 就 +1，`previous` 指向上一个世代的 id 与时刻。于是前端可以写「进程 71kijb · 第 2 次启动」，而不只是一个随机串。这也是唯一一条跨重启的短历史：记忆本体在 `episodic/semantic/procedural`，活动流在内存，世代在 `stats.json`。
## 6.15 数据目录的成本

记忆是文件，文件就有并发问题。做法是「谁先开谁写」：`brain.lock` 里写 pid，抢不到锁的实例降级为只读——不是静默失败，而是 `/api/health` 明说、写接口回 503、前端把它翻译成一句人话。陈锁（进程已死或超过 6 小时）会被接管并记一条 `reclaimed a stale lock from pid N` 的警告。同一进程重复打开是重入，直接放行（插件重复加载不该把自己锁在门外）。
## 7. 验收清单（自我评审用）

- [ ] 时间转盘拖动后，粒子大小/亮度与「遗忘预报」同步变化，且数值与服务端 `?at=` 一致
- [ ] 检索控制台发出的 query 会真的打到 `POST /api/recall`，命中的 engram 与面板高亮一一对应
- [ ] 睡眠巩固后，迁移的条目数等于报告里的 `migrated`，且画面上确实移动了同样多的 engram
- [ ] 任意两条记忆的 3D 位置在刷新后不变（确定性寻址）
- [ ] 语义冲突后能看到虚线幽灵与 `[已修正]`
- [ ] 不联网、不开服务（`file://`）时给出内置 20 条演示数据，并明确标注「离线演示」
- [ ] 手机上单指旋转、双指缩放/平移都可用；底栏不遮挡 3D 主体
- [ ] 屏幕里没有任何 emoji、圆角渐变按钮、霓虹描边卡片
- [ ] 剖面：点「剖面」后是一次 1s 级的裁剪面推进（不是瞬间少半个半球），切面行进时内壁雾状背面同步收暗，退出后自动飞回全景
- [ ] 检索：击键后能看到「环先亮 → 束上有尾迹 → 侧支依次剥出」，侧支的条数随 `score` 变化
- [ ] 目镜：情景记忆先给「当初那句话」与 `T/WHERE/WHO/FEEL`，语义记忆先给三段式与 `[已修正]` 血缘，数字与图解排在后面
